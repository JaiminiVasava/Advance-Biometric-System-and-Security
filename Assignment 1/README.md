# User Authentication using Biometric Features
**AI461 – Advanced Biometric Systems and Security | Assignment 1**

This repository contains the implementation and results for evaluating a biometric
verification system using **Euclidean distance** and **Cosine similarity** as
matching criteria.

---

## 1. Problem Statement

Given feature vectors extracted from biometric images of **100 users**, with
**10 samples per user** (144 features each), evaluate a verification system by:

- Using the **first 5 samples** of each user as **enrollment (training)** data
- Using the **remaining 5 samples** as **test** data
- Computing genuine and imposter match scores under two distance/similarity
  measures (Euclidean distance, Cosine similarity)
- Reporting the following performance analyses for each measure:
  - **A.** Genuine Score Distribution
  - **B.** Imposter Score Distribution
  - **C.** FAR (False Acceptance Rate) Plot
  - **D.** FRR (False Rejection Rate) Plot
  - **E.** Receiver Operating Characteristic (ROC) Curve
  - **F.** Equal Error Rate (EER) and Decidability Index (d′)

## 3. Methodology

### 3.1 Data Loading and Preprocessing
- The CSV is read as a `features × samples` matrix, transposed to
  `samples × features`, and reshaped into `(n_users, 10, n_features)` — i.e.
  10 samples per user (100 users × 10 samples × 144 features).
- Empty columns and incomplete rows are dropped before reshaping.

### 3.2 Enrollment / Test Split
- **Enrollment set:** samples 1–5 per user (`N_ENROLL = 5`)
- **Test set:** samples 6–10 per user (`N_TEST = 5`)
- A single **template per user** is generated by averaging the 5 enrollment
  feature vectors (mean feature vector).

### 3.3 Matching Scores
For every test sample of every user, a matching score is computed against
**all 100 user templates** (100 × 5 = 500 test samples × 100 templates =
50,000 comparisons per metric):

- **Euclidean:** score = `−euclidean(test_sample, template)` (negated so that
  a *higher* score always means *more similar*, keeping the FAR/FRR logic
  consistent across both metrics)
- **Cosine:** score = `1 − cosine_distance(test_sample, template)` (i.e.
  cosine similarity)

If the test sample's true user matches the template's user → **genuine
score**; otherwise → **imposter score**.
- Genuine scores per metric: 500 (5 test samples × 100 users)
- Imposter scores per metric: 49,500 (500 test samples × 99 non-matching templates)

### 3.4 FAR / FRR / EER / Decidability Index
- A range of 1000 thresholds is swept between the minimum and maximum score.
- **FAR(t)** = fraction of imposter scores ≥ t (wrongly accepted impostors)
- **FRR(t)** = fraction of genuine scores < t (wrongly rejected genuine users)
- **EER** = value of FAR (≈ FRR) at the threshold where `|FAR − FRR|` is
  minimized (the FAR/FRR crossover point)
- **Decidability Index (d′)**:

  d′ = |μ_genuine − μ_imposter| / √((σ²_genuine + σ²_imposter) / 2)

  A higher d′ indicates better separability between genuine and imposter
  distributions.

### 3.5 Visualization (Sections A–F)
All six plots are generated for **both metrics on the same axes** (solid line
= Euclidean, dashed line = Cosine) and combined into a single vertical figure
(`BIOMETRIC_EVALUATION_A_TO_F.png`):

- **A. Genuine Distribution** – normalized (z-scored) histogram/density of genuine scores
- **B. Imposter Distribution** – normalized histogram/density of imposter scores
- **C. FAR Plot** – FAR vs. normalized threshold
- **D. FRR Plot** – FRR vs. normalized threshold
- **E. ROC Curve** – TAR (1 − FRR) vs. FAR, with a random-classifier reference line
- **F. EER & d′** – grouped bar chart comparing EER (%) and d′ for both metrics

A summary table (`summary_metrics.csv`) and console printout report the final
EER (%) and d′ for each metric, along with the metric that performs best
based on the lower EER.
